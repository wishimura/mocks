# Web商店街 — 要件定義（開発版・ドラフト）

オンライン商店街サービス「Web商店街」を本開発する場合の要件メモ。
※ 現状の `web-shotengai/` 配下はデザインモック。本書は「製品化する場合」の要件。

---

## 1. サービス概要
- ユーザーがアバターを操作して **2.5Dの街（マーケット）を回遊**し、お店に近づくと紹介ウィンドウが出て、**BASE / Shopify の外部ECへ遷移**する。
- 友人数名（目安4人）で同時に入り、Discord等で通話しながら一緒に回るイメージ（チャット・ボイスは実装しない）。
- マーケットは **会員限定公開**。管理者が複数のマーケットを作成し、各マーケットに **店舗オーナー**が店舗を登録（出店）する。

## 2. ロールと権限

| ロール | 概要 | 主な権限 |
|---|---|---|
| **一般ユーザー** | 会員登録して街を回遊する来場者 | マーケット入場・回遊、アバター設定、お気に入り、ECへ遷移 |
| **店舗オーナー** | マーケットに出店するお店のオーナー | 自店の情報編集、建物デザイン選択、商品写真、ECリンク設定、公開/非公開 |
| **管理者（運営）** | プラットフォーム全体の運営（**固定1名**） | マーケットの作成・編集、店舗オーナーのアカウント発行、店舗管理、配置（区画割当）、一般ユーザー管理、アセット管理、お知らせ配信 |

## 3. データ構造（関係）

```
管理者(admin) ──< マーケット(Market) ──< 店舗(Shop) >── 店舗オーナー(ShopOwner)
                                   └─< 商品写真(ProductImage)
一般ユーザー(User) ──< 来訪/お気に入り >── マーケット/店舗
一般ユーザー(User) ──1 アバター(Avatar)
```

- **マーケット(Market)**：管理者が複数作成。属性＝名称 / 開催期間 / 公開状態（**会員限定**）/ 最大店舗数 / 街レイアウト（区画）。
- **店舗(Shop)**：1マーケットに複数。`market_id` と `owner(店舗オーナー)` に紐づく。属性＝店名 / カテゴリ / 紹介 / 建物デザイン（管理者が用意したテンプレから選択）/ 看板 / SNS / ECリンク(BASE/Shopify) / 公開状態 / 配置（**運営が割当**）。
  - 1人の店舗オーナーが**複数マーケットに出店**することも可。
- **一般ユーザー(User)**：会員。1つのアバター、複数のお気に入り・来訪履歴。
- **アバター・建物デザイン**：テンプレの**追加・編集は管理者のみ**。店舗オーナー/一般ユーザーは用意された中から**選択**する。

## 4. 店舗オーナーのアカウント発行フロー
店舗オーナーは自己登録せず、**契約はシステム外**で行い、管理者がアカウントを発行する。

1. **システム外で契約**し、店舗オーナーのメールアドレスを受け取る。
2. **管理者が管理画面から店舗オーナーのメールアドレスを登録**（招待メールが自動送信）。
3. 店舗オーナーが**メール内のリンクからログイン**し、アカウント情報の登録・パスワード設定を行う。

## 6. 技術スタック（MVP）

| 層 | 採用 | 備考・代替 |
|---|---|---|
| 街の描画 | **PixiJS**（or Phaser 3） | 2.5Dスプライト描画。現モックの規格（接地点=下端中央・タイル・スプライト合成）を流用 |
| UI / 管理画面 | **React + TypeScript + Vite** | 代替: Next.js / Vue |
| スタイル | Tailwind CSS | — |
| 同時接続(4人) | **Supabase Realtime（presence）** | 位置配信のみ。将来の多人数化時 **Colyseus**（ルーム=マーケット） |
| DB / 認証 / 保存 | **Supabase**（PostgreSQL + Auth + Storage） | バックエンド開発を最小化。代替: Firebase / 自前Node+PostgreSQL |
| 画像 / アセット | Supabase Storage（+CDN） or Cloudflare R2/Images | AIアート・アバター・店舗オーナーアップ画像（自動リサイズ） |
| EC連携 | URL保存→外部遷移のみ | BASE/Shopify のAPI連携・自前商品DBは作らない |
| ホスティング | **Vercel** | CDN・SSL自動。代替: Cloudflare Pages / Netlify |
| 認証ロール | Supabase Auth + RLS | 一般 / 店舗オーナー / 管理者を Row Level Security で制御。招待メール発行に対応 |

### コストを抑えられる理由
- **チャット/ボイス不要**（Discord前提）→ WebRTC/音声インフラ不要
- **同時4人**＝負荷極小、専用ゲームサーバ不要（presenceで十分）
- **EC＝外部リンク**＝決済・在庫・物流の実装ゼロ
- **マネージド構成（Vercel + Supabase）**で運用工数が小さい

## 8. 決定事項（前提）
- マーケットの公開範囲＝**会員限定**
- 店舗の区画（配置）＝**運営が割当**
- アバター・建物デザインの**追加・編集は管理者のみ**（オーナー/一般は選択のみ）
- 同時接続の上限＝**MVPは4人**、将来はより多数に拡張
- 商品情報＝当面 **EC外部リンクのみ**（自前の商品DBは作らない）
- 課金＝当面なし。**契約はシステム外**で行い、管理者がメール登録でアカウント発行（将来的にはシステム内課金も検討）
- 管理者＝**固定1名**

## 9. インフラ / 非機能（仕様対応）
- **サーバー構築** → Vercel + Supabase のマネージド
- **ドメイン** → レジストラ取得 → Vercel割当
- **SSL** → 自動発行・更新
- **バックアップ** → Supabase(Postgres) 自動バックアップ
- **同時接続** → MVPは4人/マーケット（presence）。将来 Colyseus でスケール
- **対応端末** → PC / スマートフォン（横向き全画面を推奨）

## 10. 将来検討（今回スコープ外）
- システム内課金（出店料の決済 → Stripe等）
- 来訪/ECクリックの分析、店舗オーナー向けダッシュボード
- 通報/モデレーション、運用監視、運営メンバーの権限管理
- 同時接続の大規模化（Colyseus）
- 商品情報の取込（BASE/Shopify API 連携）
